# Vulnerability feed, 2026-10-21

Window: 2026-10-13 to 2026-10-21. A section near the end lists older bugs that attackers still use.

Each row names a primary source. Verifiers checked each item against that source between 2026-10-21 and 2026-10-22. Where a fact is weaker, the row says so ("unverified", "inferred", "secondary source").

"KEV" means the CISA Known Exploited Vulnerabilities catalog, with the date CISA added the bug. All dates are 2026 unless the row says otherwise.

This is a snapshot. Versions move. Check the vendor page before you act.

## Biggest items

- **eMudhra CA keys are public.** The private keys of 8 eMudhra intermediate CAs are integers below 256. Anyone can sign a TLS certificate for any site with them. Browsers block them. Many command-line tools, language runtimes and Electron apps do not, because each one has its own trust store. Test each tool with the eMudhra quick test below.
- **Bun has no fixed release.** Bun still trusts the eMudhra chains. Its fetch also sends the full request before a `checkServerIdentity` callback can reject the server. On an untrusted network, an attacker can take the tokens that Bun tools send.
- **Self-hosted servers under attack.** Plex Media Server ("Plex2Shell", KEV 10-20), the built-in Collabora server in Nextcloud, and PHP ("PHP2Shell", unauthenticated code execution) need updates now.
- **Supply chain and account theft.** LiteLLM 1.107.0 on PyPI and Docker was a credential stealer. GhostAction steals GitHub tokens and plants workflows. The OpenCode Console leaked provider API keys.
- **Node.js security release.** A Brotli decoder bug allows remote code execution. Two bugs let an attacker skip the TLS hostname check for IP hosts. Update to 26.12.1, 24.22.1 or 22.23.4.
- **Browsers and Electron.** Chrome 156 fixes 6 Critical bugs. Electron 42 reached end of life on 10-20. Apps on Electron 42 or older get no more Chromium fixes.
- **Apple disclosures on 10-19.** Apple named a WebKit code execution bug (fixed in Safari 27) and 20 macOS Tahoe bugs (fixed in 26.7). The details are now public, so machines that skipped those updates are at higher risk.
- **Edge devices exploited in the window.** Attackers use new bugs in VPN gateways and appliances. Patch Ivanti Connect Secure, PAN-OS, Cisco Secure Email Gateway, BeyondTrust, Fortinet and Citrix NetScaler.

## eMudhra quick test

Two test hosts serve a certificate from a compromised intermediate:

- `https://dv-g3b-emudhra.we-have-a-problem.com/` chains to "emSign ECC Root CA - G3".
- `https://dv-g3b-aaa-emudhra.we-have-a-problem.com/` chains to the Sectigo "AAA Certificate Services" cross-sign.

A protected client fails with a certificate error. A client that loads the page is exposed.

Each runtime has its own trust store. One fix does not cover the others. Test each client on each machine: OS curl and git, Homebrew or distro curl, each Python (and each venv), Node, Bun, Deno, Java, uv, pip and Go tools.

Run the skill's probe with both hosts:

```sh
scripts/tls-probe.sh dv-g3b-emudhra.we-have-a-problem.com dv-g3b-aaa-emudhra.we-have-a-problem.com
```

Every row for these hosts must say `reject`. A row that says `ACCEPT` is a finding.

More checks:

```sh
# A CA bundle file. Expect "Verify return code: 20", not 0.
for h in dv-g3b-emudhra dv-g3b-aaa-emudhra; do echo | openssl s_client -connect $h.we-have-a-problem.com:443 -servername $h.we-have-a-problem.com -CAfile /path/to/cert.pem -CApath /var/empty 2>&1 | grep 'Verify return code'; done

# pip. Expect a certificate error.
python3 -m pip index versions x --no-cache-dir --retries 0 --index-url https://dv-g3b-emudhra.we-have-a-problem.com/simple/
```

Traps:

- On macOS, Apple curl and git fall back to Keychain trust when their CA bundle rejects a chain. Set `OPENSSL_X509_TEA_DISABLE=1` when you test a bundle, or the test can pass through Keychain trust.
- On macOS, do not test with `security verify-cert -c leaf`. It fails on the missing SCTs whether or not the chain is trusted, so it gives a false pass.
- Apple devices depend on revocation data. In tests, iOS simulators trusted both chains until the data downloaded, about 1 minute after boot.
- The test hosts close each connection. A client that rejects them can still leak a request to a real attacker if it checks the server only after it sends (Bun fetch does this).
- Run the test again after each change.

## No fix yet / mitigations

**Bun (no release with the eMudhra fix).**
- Keep Bun tools that carry tokens off networks you do not control.
- `SSL_CERT_FILE` with a filtered bundle replaces the /etc/ssl/cert.pem load. It blocks the AAA chain only, because Bun has the emSign root built in.
- Do not rely on fetch with `tls.checkServerIdentity` for token checks. Bun 1.3.14 writes the full request, headers and body included, before the callback rejects. It also puts the refused connection back in its keep-alive pool, and later fetches to the same origin reuse it without a check (measured up to about 300 seconds). `keepalive: false` still sends the request. `tls.ca` adds roots, it does not replace them.
- In tests, `node:tls` `tls.connect` with `checkServerIdentity` failed closed before it wrote any request bytes.
- Bun auto-install fetches a missing package at run time, over Bun's TLS, and does not check bun.lock hashes. Run scripts with `bun --no-install`.
- `bun build --compile` for another target downloads that runtime with no hash check. Pass a checked runtime with `--compile-executable-path`.

**macOS /etc/ssl/cert.pem.** No macOS update fixes this file. The incident page gives this workaround:

```sh
sudo cp -p /etc/ssl/cert.pem /etc/ssl/cert.pem.bak && sudo awk '/^(###|===) /{skip=0} /^=== .*\/CN=(AAA Certificate Services|emSign ECC Root CA - G3)$/{skip=1} !skip' /etc/ssl/cert.pem.bak | sudo tee /etc/ssl/cert.pem > /dev/null
/usr/bin/curl -sS https://dv-g3b-emudhra.we-have-a-problem.com/   # expect a certificate error
```

- Repeat it after every macOS or Command Line Tools update.
- Set `PIP_CERT=/etc/ssl/cert.pem` for /usr/bin/pip3.
- When Apple curl or git uses a CA bundle, also set `OPENSSL_X509_TEA_DISABLE=1`. git ignores `SSL_CERT_FILE` on macOS, so use `GIT_SSL_CAINFO`.

**Apple devices that still trust the chain.** Update the OS and run the quick test. Untested option for a Mac: an admin deny trust setting on the emSign root, `sudo security add-trusted-cert -d -r deny -k /Library/Keychains/System.keychain emsign-ecc-g3.pem`. Only SecTrust honors it. LibreSSL curl, Bun and Node ignore it.

**Linux distro stores that still trust the chain.** Deselect the two roots, then rebuild the store. This does not cover runtimes with their own store.

```sh
sudo sed -i -e 's|^mozilla/emSign_ECC_Root_CA_-_G3.crt|!&|' -e 's|^mozilla/Comodo_AAA_Services_root.crt|!&|' /etc/ca-certificates.conf && sudo update-ca-certificates
```

- Homebrew on Linux uses the system curl, git and store unless `HOMEBREW_FORCE_BREWED_CA_CERTIFICATES` is set.
- Node before the fixed release: `NODE_OPTIONS=--use-openssl-ca` with a fixed system store.

**Java without a .0.2 build (17, 21 and others).**
- Replace `$JAVA_HOME/lib/security/blocked.certs` with the file from the OpenJDK advisory. First check that the old file's entries are all in the new one (`comm -23 <(sort old) <(sort new)` prints nothing). Repeat after each JDK update, because a new JDK brings back the stock file.
- Or set `-Dcom.sun.net.ssl.checkRevocation=true -Dcom.sun.security.enableCRLDP=true` in `JAVA_TOOL_OPTIONS`. These flags fail closed when offline. They do not reach apps started from the Finder or GraalVM native images.
- GraalVM native images need a rebuild by their vendor.

**Google Cloud CLI.** No fix. Its bundled CA files trust both roots. Point it at a fixed bundle: `gcloud config set core/custom_ca_certs_file /path/to/fixed/cert.pem`.

**AWS CLI before 2.38.4.** `aws configure set default.ca_bundle /path/to/fixed/cert.pem`. Remove the setting after you update.

**Python gRPC (grpcio).** Its bundled roots.pem trusts the emSign root, and channels without explicit roots use it. Set `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH` to a fixed bundle (certifi 2026.10.19 or later) before the program imports grpc. If that path is missing or unreadable, grpcio falls back to its bundled roots, so check that the file exists.

**GitHub Actions.**
- Runner 2.338.0 bundles Node 24.21.0 and 20.20.2. Both trust the emSign root, and JavaScript actions (checkout, cache, setup actions) run on them. Wait for runner images with fixed Node.
- On Ubuntu runners, install the fixed ca-certificates as the first step.
- macOS runner images may carry revocation data from before the block (inferred). Do not rely on SecTrust there. Use a filtered bundle with `OPENSSL_X509_TEA_DISABLE=1`.

**OrbStack.** No release ships Docker Engine 29.9.2 yet. Pull images by digest. Do not run `docker login` or `docker push` on untrusted networks.

**Comet and CEF apps (for example Spotify).** No fixed build. The newest stable CEF is 154.0.34 (10-05). Keep them closed or remove them.

**Electron apps on end-of-life majors.** Apps on Electron 42 or older get no Chromium fixes. Use the web version or quit the app until the vendor ships an update.

**Pillow.** The OpenJPEG 2.5.4 that Pillow wheels bundle has a heap overflow (GHSA-78g4-xqwv-q3g8) with no OpenJPEG fix yet. Do not set `PILLOW_ALIGNMENT`: CVE-2026-114501 has no fix.

**Linux "PwnEscape".** Ubuntu had no fix when checked. Do not run untrusted guests on an unpatched host. Do not treat containers on an unpatched VM kernel as a sandbox.

**Older lines with no fix.** PHP 7.4, 8.0 and 8.1 get source patches only, with no official builds. Drupal 8.9, 9.x and 10.x before 10.6 have no fix for SA-CORE-2026-014. Move to a supported line.

**Apple 26.7.2, 15.8.2 and 27.2.** Apple has not published the security content. Install them when they ship.
